# Практика · тестовая витрина курсов

GitHub Pages размещает только `public/`. Отдельная Supabase-функция `course-shop` хранит покупки, проверяет тестовые платежи, связывает покупку с Telegram и выдаёт два файла с Яндекс Диска после одобрения модератором.

## Сценарий

1. Покупатель выбирает один из трёх пакетов и переходит на тестовую страницу Robokassa.
2. Сервер проверяет подпись уведомления Robokassa, сумму и номер заказа. Возвращение покупателя на витрину только открывает статус заказа.
3. Покупатель открывает одноразовую ссылку бота и нажимает Start. Покупка связывается только с одним аккаунтом.
4. Бот создаёт временное приглашение с заявкой на вступление. Передача ссылки другому человеку не даёт ему оплаченного доступа.
5. Владелец одобряет заявку кнопкой в боте либо в самом Telegram. Перед отправкой файлов проверяется фактическое членство в канале.
6. Бот скачивает `codex-lesson.txt` и `codex-practice.xlsx` с Яндекс Диска и отправляет покупателю лично. В тесте все пакеты дают один канал и одинаковые материалы.

Оформление проходит на отдельном сайте. Robokassa получает `IsTest=1` и использует отдельные тестовые пароли. В режиме `yookassa_test` сервер сверяет магазин и платёж через API ЮKassa. Перед боевым запуском заново проверяют правила Telegram, эквайринг, чеки и размещение.

## Локальный запуск

Node.js 22:

```text
npm ci
npm run setup -- init
npm test
npm run check
npm start
```

Открыть `http://localhost:4174/`. Без ключей можно посмотреть витрину; оплата честно отключена. Локальная PostgreSQL-база PGlite хранится в `.local/db`. Перезапуск не удаляет покупки. Публичных локальных административных панелей нет.

## Настройки

Секреты находятся в `.local/secrets.env`, исключённой из Git. На сервере их добавляют в Secrets Supabase. Значения в чат, журнал и скриншоты не отправлять.

| Переменная | Назначение |
| --- | --- |
| BOT_TOKEN / BOT_USERNAME | Отдельный Telegram-бот, username без @ |
| ADMIN_CHAT_ID | Проверенный владелец и модератор |
| COURSE_CHANNEL_ID | Числовой ID отдельного закрытого канала |
| TG_WEBHOOK_SECRET | Секрет входящих Telegram-событий |
| SHOP_ADMIN_SECRET | Серверный секрет настройки/worker и HMAC покупок |
| PAYMENT_MODE | `robokassa_test` для Robokassa или `yookassa_test` для ЮKassa |
| ROBOKASSA_MERCHANT_LOGIN | Идентификатор магазина из раздела «Мои магазины» |
| ROBOKASSA_TEST_PASSWORD_1 / ROBOKASSA_TEST_PASSWORD_2 | Два разных пароля из блока тестовых платежей Robokassa |
| YOOKASSA_SHOP_ID / YOOKASSA_SECRET_KEY | Только тестовый магазин ЮKassa |
| SITE_URL | Полный URL витрины с завершающим `/` |
| YANDEX_DISK_TOKEN | OAuth чтения Яндекс Диска |
| YANDEX_TEXT_PATH | `disk:/nobel_lesson3/codex-lesson.txt` |
| YANDEX_XLSX_PATH | `disk:/nobel_lesson3/codex-practice.xlsx` |
| MATERIAL_TXT_SHA256 / MATERIAL_XLSX_SHA256 | Контрольные суммы разрешённой версии файлов |

`npm run setup -- init` создаёт недостающие случайные секреты и вычисляет контрольные суммы материалов. Настоящие ключи автоматически не создаются. Не меняйте `SHOP_ADMIN_SECRET` без плана миграции: от него зависят ссылки существующих покупок.

## Подключение Telegram

Создать нового бота через @BotFather. В закрытом канале добавить бота администратором с правом приглашать пользователей. Не использовать бота чужой работающей интеграции.

```text
npm run setup -- owner
```

Владелец открывает выданную одноразовую ссылку и нажимает Start в течение 10 минут. Затем:

```text
npm run setup -- check-owner
```

Сохраняется проверенный ADMIN_CHAT_ID. Обычный первый посетитель владельцем не становится. Если событие добавления в канал доступно и однозначно, сохраняется COURSE_CHANNEL_ID. При действующем webhook getUpdates не используется.

Команды владельца: `/requests` — ожидающие заявки; `/retry` — повторить ошибки. Покупатель: `/status` — состояние доступа; `/materials` — повторить материалы, если он всё ещё состоит в канале.

## Supabase и публикация

1. Создать отдельный разрешённый тестовый проект. Не использовать существующую рабочую базу без согласования.
2. Проверить схему и выполнить `supabase/migrations/202611220001_course_shop.sql`. Создаётся отдельная закрытая схема `course_shop`; анонимным ролям запрещены таблицы и RPC.
3. Добавить Secrets. Доступ к БД использует стандартные серверные SUPABASE_URL и современные SUPABASE_SECRET_KEYS либо SUPABASE_SERVICE_ROLE_KEY; возможен SERVER_DB_KEY.
4. `npm run bundle` создаёт самостоятельный файл `.local/dashboard/course-shop.ts`. Его можно вставить в редактор функции `course-shop`. Стандартный JWT для этой функции выключен: публичные операции имеют ограниченный контракт, покупка проверяется по непрозрачному ключу, Telegram и административные маршруты — по собственным секретам.
5. В `public/config.js` задать `endpoint: "https://PROJECT.supabase.co/functions/v1/course-shop"`. Секретов в config.js нет.
6. В `.local/deployment.json` сохранить `{"endpoint":"https://PROJECT.supabase.co/functions/v1/course-shop"}` и выполнить `npm run setup -- register`. Проверяются права бота и регистрируется `/telegram` с нужными allowed_updates.
7. В технических настройках магазина Robokassa выбрать алгоритм `SHA256`, ввести два разных пароля в блоке «Параметры проведения тестовых платежей». Указать `ENDPOINT/robokassa-result` как Result URL с методом POST. Для Success URL указать `SITE_URL?order=return` с методом GET. В режиме ЮKassa уведомления направляются на `ENDPOINT/payment`.
8. Для автоматических повторов при закрытых окнах создать защищённый периодический вызов `POST ENDPOINT/worker` с заголовком X-Shop-Admin-Secret. В Supabase можно использовать pg_cron + pg_net и Vault. Секрет не помещать в публичный SQL. Без этого для повтора ошибок остаётся `/retry`; локальный worker зависит от работающего компьютера.
9. Для GitHub Pages выбрать Source GitHub Actions. Workflow публикует только `public/`. Боевой коммерческий магазин требует подходящего размещения и отдельной приёмки.

## Яндекс Диск и учебные материалы

`scripts/materials.py` создаёт ровно два тестовых материала в `.local/course-materials`; реальные курсы туда не вшиты. TXT содержит маленький урок, XLSX — задания, статусы и формулы прогресса. Исходники можно использовать для повторной генерации учебного примера.

Файлы загружаются в `nobel_lesson3` на Диске. OAuth разрешает чтение, без записи/удаления. Право `cloud_api:disk.read` относится ко всему Диску; программное ограничение двумя путями не является ограничением самого OAuth. Токен остаётся серверным. Проверяются разрешённый HTTPS-хост скачивания, размер до 10 МБ и SHA256. При замене материала обновите контрольную сумму после проверки версии.

## Проверка и ограничения

Тесты проверяют расчёт подписи Robokassa и обработку уведомления, в том числе отказ при неверной сумме или номере заказа. Сценарий от подтверждения до выдачи файлов проверяется на локальной базе PGlite с тестовыми заменами внешних сервисов. Работа реальных аккаунтов проверяется отдельно.

Живая приёмка: настоящий тестовый платёж → серверное подтверждение → Start → заявка → решение модератора → получение двух настоящих файлов с Диска. Дополнительно отменённый платёж, чужой аккаунт, повтор события и ошибка второго файла.

Возвраты, подписки, несколько каналов и боевые платежи не входят в эту тестовую версию. Telegram не даёт ключа идемпотентности отправки файла: при аварии между успешной отправкой и фиксацией результата редкий дубль доставки теоретически возможен. Бесплатный Supabase имеет квоты и может приостанавливаться.
